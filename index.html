Root cause: two things stack. (1) The reindex flushed the warm cache, so every query cold-reads 2,048 segments from object storage. (2) The price < 100 filter matches 61% of the namespace, so it is applied post-merge and narrows nothing; the scan cannot lean on it.

Fix shape: ship a rewrite that warms the namespace and adds a selective guard (stock > 0, 61% → 9%) so the merge runs on a small candidate set. Cache-only pin is the conservative alternative. Both are gated below.
